## 1. 目标与现状

在实际请求快照统计的基础上，统一模型窗口预算、发送投影、上下文详情和压缩触发条件。保留用户完整原始历史，让长会话在模型窗口内继续工作，同时减少重复携带大块工具结果。

沿用 v0.8.2 的最后一次主模型实际请求及其响应快照：当前占用只计算真正外发的输入与该次输出，累计输入 / 输出 / 缓存仍逐请求记账。本版管理路径已取消 2,400 / 8,000 / 2,000 Token 与 32 轮的固定内容裁剪，改用模型窗口、真实输出分配及最终协议请求预检；有界工具步骤跨轮加密保存，压缩只改变发送视图。

## 3. F01：统一上下文管理地基

- 分开原始历史、模型发送视图、最后实际请求快照与累计用量。压缩只改变发送视图，不删除用户历史，不改写计费账本。
- 保留结构化 user / assistant、附件、工具调用 / 结果及必要协议状态，按闭合工具步骤组织；新请求开始保存此前未持久化的工具证据。旧记录缺失的结果明确为不可恢复，不能由活动摘要伪造。
- 统一来源身份、记录顺序、revision / generation、请求截止点与覆盖范围。工具长循环需支持轮次内已闭合步骤的覆盖，不只依赖 throughTurnId；当前提问和未闭合工具组受保护。
- 以实际请求的模型窗口、max_tokens / max_output_tokens、整轮剩余预算和安全余量计算预算，替换固定激进历史裁剪；存储分页大小和前端 500 条驻留上限不再决定模型保留范围。
- 普通思考默认不反复发送、不进摘要；签名 / 加密推理状态按协议规则保留，切换模型时重新验证兼容性。近期工具调用、参数和结果保持配对，已完成写工具不因恢复或压缩重复执行。
- 最终协议请求先完成序列化和计数预检，再冻结发送；压缩判断、发送与详情使用同一份材料。圆环继续展示最后实际主请求及其输出，预留空间不冒充实际占用。
- 固定系统前缀、工具定义顺序及未变化历史尽量稳定；权限、设置与来源变化显式产生新版本，不靠每轮重写全部历史来管理上下文。
- 上下文续接独立于长期记忆提取 / 使用开关，复用现有 SQLite、聊天加密、回执、来源与事务能力。持久化数据计入会话容量，落点保持 APP_ROOT。
- schema 22 增加加密步骤、续接检查点与租约；旧 vault 摘要不自动迁移为新检查点。管理路径的记忆维护只做提取，取消旧 SUMMARY 队列任务，避免重复发布。

## 4. F02：窗口阈值与上下文压缩

- 以「有效续接摘要 + 近期完整内容 + 当前必要输入」替换较早发送内容。通用结构化摘要作为跨供应商基础，原生 compaction 后置至兼容性与恢复验证完成。
- 每次主请求、工具往返与断流续答前预检。自动压缩默认开启，阈值 80%（可设 65–95%），压缩后目标约 60%，仍受实际输出与安全余量约束；设置在「AI 对话 → 运行限制 → 上下文管理」，保留原保存 / 取消 / 恢复默认样式。
- 工具结果沿用有界正文，压缩较早闭合来源组；保留目标、最新约束、确认结论、任务进度、待办、失败状态、来源和完整写回执，不带普通思考。最新活动工具组与已确认续答片段受保护，近期两轮仅在能够容纳时保留。
- 校验摘要结构、来源与覆盖，使用 revision / generation / 内容指纹 CAS 发布；停止、失败、未解锁、输入换代或无预算时保留原视图。网络调用不在 SQLite 写事务内。
- 压缩只向本轮选择的聊天目标发送同会话合格内容，不暗中换用另一供应商，也不把摘要写成长期记忆或提高工具授权。
- 压缩实际请求独立记账，并计入对应会话累计用量；压缩请求本身不替换回答主请求的圆环快照。自动压缩设防重复触发和无进展保护，单个必需输入过大明确报错。
- 摘要候选在内存中分段生成，最终预检与来源复核通过后只发布一次；格式、终态、来源和回执缺失均拒绝。软门槛下失败仅在完整原视图仍可容纳时继续，硬超限拒绝发送。原回复处显示压缩进度，可用现有停止入口取消。

## 5. 验收要求

验证发送 / 占用 / 阈值的一致性、压缩前后数值变化、摘要覆盖与原历史保持、长工具结果的关键证据与配对、模型切换、断流恢复、停止 / 压缩失败、原地重试与旧摘要失效。核对普通思考与协议状态的供应商差异，以及稳定前缀的缓存行为。

先验证 F01：超过 32 轮的连续任务仍能按预算携带历史；近期工具结果跨轮可读、调用 / 结果不拆对；最终实际请求与审计同源，模型切换 / 重启 / 停止 / 原地重试保持正确来源与截止点。再验证 F02：多次压缩、长单轮工具链、来源改口 / 删除、失败保留及压缩用量可核对。

压缩产生的实际模型请求仍逐次记账，计费用量只增加、不因上下文变短而扣减。需要针对真实供应商验证协议、摘要质量和缓存口径；本地夹具不作为原生压缩兼容承诺。已实现应用代码、schema 22 及界面接入；发布工作流和默认发行版本仍保持 v0.8.2，本轮不暂存、提交、推送或发布。
