# 实时流式、过程折叠与缓存口径规格（v0.8.3 F03 / F04）

> 2026-11-18。基于已定 [UI/UX](ui-ux.md)；范围见 [v0.8.3 清单](../../state/v0.8.3-features.md)。不新增数据库表或列，schema 保持 22。

## 1. 根因

- **F03**：`AiService.runTurn` 在工具模式下把每次响应的增量写入 `DeltaBuffer`，只有确认无工具调用才回放；工具步骤的正文和思考不回放也不保存。前端 `aiStream → useAiChatTurn → AiAssistant` 本身逐增量渲染，无需调整节奏。
- **F04**：`ChatUsageRepository` 把缺失的 `cache_read_tokens` 视为未回报。开发库中同一目标 74 条对话请求有 60 条回报命中（最小 9,088）、14 条字段缺失、0 条回报 0，缺失集中在压缩后首个请求和摘要请求，即零命中时字段被省略。

## 2. F03 后端

### 2.1 流式

每次模型响应的 `text` / `reasoning` 增量直接交给轮次监听器，取消缓冲与回放。中断、超时、插话衔接沿用原非工具路径：本次已推送的正文和思考并入已确认前缀。工具参数与工具结果仍不进入 SSE。

### 2.2 过程步骤

一次响应以工具调用结束时，把它的思考和正文记为一个过程步骤：

| 字段 | 含义 |
|---|---|
| `anchor` | 步骤结束时已有的工具活动数（0–1200）；展示在序号大于它的工具行之前 |
| `reasoning` | 该次响应的思考，可空 |
| `text` | 该次响应的过渡正文，可空 |
| `truncated` | 触及保存上限后置真 |

思考与正文都为空时不产生步骤。全部步骤的文本合计最多 65,536 UTF-8 字节、256 步；超出时优先保留正文，再保留思考，不截断半个字符，之后的步骤只把最后一步标为 `truncated`。供应商在工具已关闭时仍返回调用、或步骤额度用尽而放弃执行的响应，同样记为步骤，不残留在回答区。

步骤属于界面元数据：不进入发给模型的消息、上下文步骤表、摘要来源和容量以外的任何账本。发给模型的助手工具消息仍由原响应构造，行为不变。

### 2.3 保存与读取

步骤随 `toolActivities` 一起写入轮次 `result_meta`（聊天加密）：运行中的检查点和终态各写一次全量，键为 `processSegments`。终态超过 `result_meta` 上限而收缩时不保留步骤。原地重试沿用原轮次的步骤，与沿用工具活动一致，`anchor` 继续有效。

以下出口返回 `processSegments`（没有则为空数组）：流式 `done` 与普通聊天结果、`GET /ai/turns/{requestId}`、历史分页的助手消息、运行快照。内容已清理的轮次返回空数组。

### 2.4 SSE 事件 `process`

步骤产生后立刻发送：

```json
{ "requestId": "…", "sessionId": 1, "processSegments": [ … 全量 … ], "reply": "已确认的回答前缀", "reasoning": "已确认的思考前缀" }
```

客户端收到后用 `processSegments` 整体替换，并把回答区和思考区重置为 `reply` / `reasoning`，随后的增量在其后追加。托管流（v2）的运行态同样重置内存中的回答 / 思考并记住步骤；重新订阅时先补发一帧 `process`（`reply`、`reasoning` 为空），再补发当前步骤已累计的正文与思考。

## 3. F03 前端

- `aiStream` 解析 `process` 帧和结果视图里的 `processSegments`；逐项校验类型、范围，丢弃非法项。
- `useAiChatTurn` 增加 `process` 事件；状态查询结果同样规范化步骤。
- `AiAssistant`：收到 `process` 时替换步骤并重置回答 / 思考；快照、终态和历史行带步骤时原样采用。渲染顺序改为「压缩提示 → 过程 → 思考过程 → 回答」。
- `ToolActivityGroup` 接收步骤，在工具列表中按 `anchor` 插入：思考为默认收起的子折叠，过渡正文按 Markdown 渲染。标题行、自动折叠与手动选择逻辑不变。

## 4. F04

- `ChatUsageRepository` 的实测行：`usage_source = provider` 且已结算的请求缺少 `cache_read_tokens` 时，若同一 `target_fingerprint` 存在任何回报过该字段的记录，则命中按 0。Anthropic 口径（缓存读不含在输入内）的输入完整性判断同步接受这一推断；缓存写入缺失仍视为不完整。会话累计、单轮累计与请求分页共用同一规则。
- `AiUpstreamClient.usageOfChatCompletion`：`cached_tokens`、`prompt_cache_hit_tokens` 都缺失而 `prompt_cache_miss_tokens` 与输入存在时，命中数取 `max(0, 输入 − 未命中)`。
- 不改写已保存记录，不改变每日预算与计费账本。

## 5. 验证

- 后端：工具路径增量在响应期间到达监听器；工具步骤生成步骤并可从状态、历史读回；无工具回答不产生步骤；步骤上限截断；托管流重订阅顺序；缓存推断的三种情形（已证明目标缺失、未证明目标缺失、未知用量）；未命中字段解析。
- 前端：`process` 帧解析、消息状态重置、过程内排序与折叠、历史读回。
- 构建、便携落盘与静态审计按[测试规范](../../test/TESTING_GUIDELINES.md)复跑。真实供应商的逐字节奏与实机观感另行验收。
