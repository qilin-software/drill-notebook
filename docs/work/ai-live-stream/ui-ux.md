# 实时流式与过程折叠 UI/UX（v0.8.3 F03）

> 2026-11-18。范围见 [v0.8.3 清单](../../state/v0.8.3-features.md#4a-f03实时流式与过程折叠)，事件与存储见[规格](spec.md)。折叠方式由用户指定参考 Codex / Qoder 桌面端：过程实时可见，结束后收成一行，可展开查看。

## 1. 一条助手消息的结构

自上而下固定为四块，前三块没有内容时不显示：

| 顺序 | 区块 | 内容 | 默认状态 |
|---|---|---|---|
| 1 | 上下文压缩提示 | 沿用现有灰色折叠提示 | 不变 |
| 2 | 过程 | 已结束步骤的思考、过渡正文和工具记录，按发生顺序 | 运行中展开，结束后折叠 |
| 3 | 思考过程 | 当前（最后）一次模型响应的思考 | 运行中展开，结束后折叠 |
| 4 | 回答 | 当前（最后）一次模型响应的正文 | 始终显示 |

「过程」沿用现有工具记录的标题行（状态图标、摘要标题、「N 次工具调用 · 耗时」、展开箭头），不新增第二个折叠入口。此前「思考过程」显示在工具记录上方，现改到其下方，与发生顺序一致。

## 2. 运行中的状态流

1. 模型开始响应：思考逐字出现在「思考过程」，正文逐字出现在「回答」，末尾显示流式光标。
2. 该次响应转去调用工具：刚显示的思考与正文从 3、4 区移入「过程」末尾，随后出现对应工具行；3、4 区清空，等待下一次响应。
3. 下一次响应继续按第 1 步流式显示，可重复多次。
4. 最后一次响应没有工具调用：它的正文就是最终回答，保留在「回答」。
5. 回答结束：「过程」和「思考过程」自动折叠；用户手动展开或折叠过的选择保持不变。

过程内的排列：每个步骤先显示该步思考（子折叠，默认收起，标题「思考过程」），再显示过渡正文（按 Markdown 渲染，弱化字色），之后是该步触发的工具行。没有思考或过渡正文的步骤只显示工具行。

## 3. 历史与恢复

- 重载历史、切换会话后，带工具的回答显示折叠的「过程」行，展开可见当时的思考、过渡正文和工具记录。
- 运行中重新连接或切回会话：已结束步骤从「过程」恢复，当前步骤继续流式显示。
- 本版之前保存的回答没有过程文本，「过程」只显示工具行，与现在一致。
- 过程文本超过保存上限时，在被截断的那一步末尾显示「（过程文本过长，后续未保存）」，不影响最终回答。

## 4. 边界

- 复制、引用、导出、标题生成和会话内跳转预览只使用最终回答，不包含过程文本。
- 过渡正文不提供单独的复制 / 重新生成按钮；选中文字后的「复制 / 引用」浮层照常可用。
- 停止或失败时，已移入过程的步骤保留，当前步骤已显示的正文按现有规则作为部分回答保留。
- 不新增设置项。

## 5. 验收表现

- 启用工具的普通问答（未触发工具）：思考与正文逐字出现，不再整段跳出。
- 触发一次工具：先看到思考和过渡正文流出，工具开始时它们收进「过程」，工具结束后最终回答逐字出现；结束后「过程」自动折叠为一行。
- 展开「过程」：顺序为「思考 → 过渡正文 → 工具行」，多步时依次排列。
- 关闭并重新打开会话：展开「过程」内容与结束时一致。
