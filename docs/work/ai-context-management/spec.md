# 上下文管理与窗口压缩规格（v0.8.3）

> 2026-11-17，已实现；超窗恢复、摘要截断、关键原话 / 回执保护及长历史读取修正通过工程验证。范围与此前 harness 调查统一见 [v0.8.3 清单](../../state/v0.8.3-features.md)，源码分工见[实现说明](implementation.md)，结果见[验证记录](qa.md)。本文维护现行机制，验证结果单独记录。

## 1. 从已有机制继续建设

沿用 `ConversationProjection → ChatContextAssembler → ChatContextPlan` 的来源、代数和不可变计划，增加 `ContextCoordinator → PreparedRequest`，统一最终请求预检、压缩和发送。`RequestContextAnalyzer / ModelContextSnapshot` 继续从最终实际请求记录占用。

管理路径已取消原先 2,400 Token 近期历史、8,000 Token 计划输入、2,000 Token 提问与 32 轮的固定内容裁剪。按模型窗口读取合格历史，结构化工具步骤参与同一投影；兼容夹具保留旧路径，不作为新客户端的默认策略。

## 2. 四类数据各司其职

| 数据 | 内容与用途 | 变化规则 |
|---|---|---|
| 原始会话记录 | 用户和助手正文、附件引用、实际工具调用 / 结果、来源与回执、必要协议状态 | 压缩不修改；用户编辑、重试替换或空间清理通过现有事务产生新版本 |
| 模型发送视图 | 有效摘要、保留的原文、当前输入、授权资料与工具定义 | 每次请求按版本、协议和预算生成；取舍必须有来源及理由 |
| 最后实际主请求快照 | 最终实际发送输入的组成和该次输出 | 沿用 v0.8.2 圆环 / 详情语义；未发候选和输出预留不算实际占用 |
| 使用量账本 | 各次供应商回报的输入、输出与缓存，含本会话压缩请求 | 已发生用量不因原文删除或视图变短扣减；压缩、标题和长期记忆维护标记不同用途 |

上下文续接与长期记忆分别控制。新检查点使用聊天加密，不依赖记忆启用或自动提取。管理路径从原历史重建，不把旧 vault 会话摘要自动迁移为新检查点；后台记忆维护只执行提取，并取消旧 SUMMARY 队列任务。旧摘要仍保留在原表供兼容路径使用。

## 3. 结构化记录与完整步骤

上下文步骤带 `sessionId / turnId / requestId / entryId / sequence / revision / kind / fingerprint`，以及供应商、协议和模型身份；加密载荷保留工具调用 ID、名称、参数、结果及已确认写入的回执标识。来源引用指向真实轮次、闭合步骤、消息、附件或资料版本，不用活动概述替代原结果。

- 当前用户输入、明确选择的当前附件和正在完成的工具组受保护。
- 工具调用与结果组成闭合步骤，步骤内部可包含多项并行调用；不能只留下结果、丢失调用，或把尚未完整收到的调用当成已执行。
- 近期闭合步骤尽量按原样发送；较早长结果可使用稳定的摘要 / 关键片段和可追溯引用。数据内容继续保持不可信资料身份，不升级为 system / developer 指令。
- 只保存实际提供给模型的有界结果和必要结构，不保存原始网络 HTML、鉴权头或整份网页请求日志；正文加密、已有正文只引用，不另复制完整会话。工具记录与摘要都纳入会话空间预算。
- 普通思考可继续供用户查看，但默认不在后续轮次反复携带、不进入压缩摘要。必须回传的签名 / 加密推理块按协议保留，不截成半块，也不跨不兼容模型伪造回放。
- 旧版本没有保存的工具结果保持缺失；需要资料时重新通过有权限的读取获得，不能从工具活动记录反推出「原始结果」。

对写工具，来源条目关联原幂等回执与业务事务。恢复从已经确认的步骤继续；压缩和上下文重组都不构成再次执行的理由。

## 4. 模型窗口预算

固定本次供应商与模型窗口 `W`，按整轮剩余额度计算请求输出上限 `R` 和协议 / 估算安全余量 `M`，计算：

```text
安全余量 M = max(512, floor(W / 10))
可用输入 H = W - R - M
软压缩门槛 S = min(floor(W × 用户阈值), H)
压缩后目标 T = min(floor(W × 60%), H)
固定规则 + 工具定义 + 摘要 + 原文 + 当前输入 + 资料 + 图片 / 协议状态 ≤ H
```

`R` 来自最终请求的 max_tokens / max_output_tokens，并受模型能力和整轮剩余输出预算约束。压缩前只预检主请求预计输出，不提前占用它的整轮额度；摘要结束后按剩余额度重新包装、预检并预留实际主输出。摘要分配另行保留最终回答额度。图片成本计入输入，避免同时作为图片预算和文本 base64 重复计数。

自动压缩默认开启，阈值默认 80%，可设置 65–95%；压缩后目标约 60%，两者均受必需输入和硬预算约束。设置入口为「设置 → AI 对话 → 运行限制 → 上下文管理」，保存 / 取消 / 恢复默认沿用原表单。近期原文额度从剩余预算分配；最近两轮仅在能够容纳时保留，最新活动工具组和断流续答的已确认片段保持完整。

历史倒序按 16 轮分页读取，恢复原顺序发送。前端 500 条仅是展示驻留限制。扫描保护为 16,384 轮、32 MiB、30 秒；触发时返回 `413 CONTEXT_SCAN_LIMIT`，不把「未扫描」当作「没有历史」。单轮步骤另有 4,096 项 / 32 MiB 保护，触发 `CONTEXT_HISTORY_SCAN_LIMIT`。

有预算时保留连续原历史；需要压缩时从较早闭合记录选取来源组，工具结果沿用既有有界正文，再生成摘要。当前提问、必要规则或受保护活动组自身就超限时返回 `CONTEXT_TOO_LARGE`，不靠静默删除来伪装成功。

## 5. 同一条准备与发送链路

```text
会话记录 / 有效检查点 + 本次受理快照
                    ↓
ContextPlan：来源、权限、分组、截止点、预算
                    ↓
协议适配：消息、工具定义、推理状态、图片、实际输出参数
                    ↓
PreparedRequest：最终请求体 + 组成分析 + 版本身份
                    ↓
预检 → 必要时压缩并重建 → 冻结 → 发送 → 实际快照与用量
```

`PreparedRequest` 是新增的内部边界：各协议完成真实请求包装后进行计数和校验，冻结后禁止再拼接影响上下文的内容。HTTP 凭证不进入上下文对象与详情。请求详情复用最终请求分析，保持实际输入和本地组成估算的区分。

圆环继续表示最后实际主请求的输入加该次输出；压缩判定使用下一次待发送请求预检，因为新提问、工具结果、模型或权限可能变化。预检数值与实际快照来自同一组材料，但输出预留不混入圆环。压缩模型请求独立记账，不把它的短提示词当成回答主请求的新占用。

新轮次处于准备阶段，或准备失败且没有实际主请求时，仍显示上一份有效主请求快照。只有未修改的 begin / end 追加能够解释历史版本增量时才允许保留；编辑、清理、换代及原地替换继续使旧快照失效。较新的主请求确实发送过但快照不可读时，显示未知，不能用更早请求冒充。

工具往返按「原受理快照 + 已确认的新步骤」生成后续计划。HTTP 重试沿用冻结请求；断流恢复明确保留既有内容并创建续接请求；手动原地重试使用原轮截止点。后续会话改选、页面变化和迟到响应不能改写已经受理的上下文。

## 6. 检查点、版本与单一发布者

每份摘要记录自身版本、来源条目 / 步骤覆盖、内容指纹、上下文代数、策略与记忆边界；覆盖使用 TURN / STEP / LEGACY / ANCHOR 的真实身份，不以单一轮次水位代替覆盖。保留原文的条目与摘要覆盖不重复计入发送视图。

覆盖必须能细到轮次内闭合步骤，支持一轮内长工具循环接近窗口。当前用户输入、未闭合组和近期保留组不被旧摘要整段替换；不同会话、作用域或手动重试截止点之外的内容不能混入。

复用现有 SQLite、加密、revision / generation、lease / CAS、回执与停止机制。网络摘要生成在事务外进行，发布前重新核对来源；编辑、清理、重试、换代或授权撤回使不匹配的检查点失效。停止、超时、失败及 CAS 冲突都保留旧视图。上下文协调器作为检查点的单一发布者，长期记忆维护不再独立覆盖新上下文检查点。

schema 22 新增 `ai_context_entry`、`ai_context_checkpoint` 与 `ai_context_compaction_lease`，使用聊天域的加密和容量策略；正文清理、原地重试、上下文换代与记忆授权撤回同步处理相关派生状态。记忆敏感工具结果被撤回后不继续进入新请求，确认遗忘会使相关摘要失效并恢复合格原历史。表和迁移见[数据模型](../../state/data-model.md)，不新增外部存储。

## 7. 压缩算法接入点

通用摘要字段为 `goal / constraints / decisions / completed / pending / unknown / sources / receipts`：保留最新要求、已确认结论、任务状态、来源和写回执。摘要来源不含普通思考，图片只保留引用占位，不推测图片内容；提示词区分用户要求、助手陈述和低优先级工具资料。

仅向本次选择的聊天模型发送本会话合格内容，关闭摘要请求的工具；合并此前摘要与新覆盖记录。校验全部字段、来源白名单及模型回执为空；完整回执由应用从实际工具结果确定性提取。缺终态、截断、工具调用及无效格式不能发布，包括 OpenAI `length` 和 Anthropic `max_tokens`。摘要和来源在内存中多段生成，最终重建请求预检通过后仅发布一次；结构与覆盖校验不保证语义无损。

单个历史来源组过大时，将合格记录按原顺序完整分片，携带原角色、消息序号、偏移、总长度与来源。该来源的所有必要片段成功并通过校验后才加入覆盖，不能只摘要前半段便删除后半段原文。供应商返回上下文超限时缩小摘要批次；分片从未完成的位置重试，输入限额按约 2/3 递减，最多 3 次超限调整。

同一输入指纹使用租约防止重复压缩，每次准备最多 32 次摘要调用，加密前检查点载荷最多 16 MiB、覆盖最多 65,536 个来源（仍计入会话容量）。达到软门槛后继续向约 60% 目标压缩，不因刚低于 80% 便提前结束；无足够收益则停止。后续可选压缩失败时，已完整生成、来源有效且满足硬预算的候选可以保留并发布，标记目标未达到后继续回答；未完成的来源组不加入覆盖。没有这类候选时，只有完整原视图仍满足硬预算且来源有效才允许回退；硬超限拒绝发送，停止、版本冲突及存储失败均保留原历史和旧检查点。

普通可用请求不读取仅供新压缩使用的任务锚点和记忆边界。可选压缩的本地元数据读取、租约获取或检查点保存失败时，只要来源未变化且完整原视图仍满足硬预算，就回退原视图继续回答；保存失败的摘要不能参与发送，也不能显示压缩完成。硬超限无法回退时明确报本地存储错误。发送前复核把实际版本 / 授权变化与存储读取异常分开：后者为 `CONTEXT_STORAGE_FAILED`，保留脱敏后的原因，不冒称会话内容已变化。

摘要 HTTP 重试使用独立的冻结请求和重试计数，沿用现有重试设置，不进入主回答重试循环。一次请求准备的摘要总时长上限 120 秒、单次摘要请求上限 60 秒，实际还受整轮剩余时间限制，并为最终回答保留输出及 5–60 秒时间。摘要用量以 `CONTEXT_COMPACT` 独立记账并进入本会话累计，共用运行许可和停止入口，不自动产生长期记忆。合法回退恢复回答时清除已失效的摘要重试报错；硬失败仍保留具体错误。

摘要返回 `CONTEXT_SUMMARY_INVALID` 时，每次摘要最多修复一次：保留同一份完整来源、当前任务及写回执，只增强格式要求，不把失败摘要当作新的历史。修复重新核对窗口、剩余输出、时间、停止与来源版本，仍受上述总预算限制；修复成功才继续，持续无效时按原候选 / 原视图回退规则处理。

已受理请求在没有正文时失败，也保存有界、脱敏、加密的错误和稳定助手消息身份。原回答位置显示具体报错，重新打开历史仍可读回，沿用原重新生成入口；不把失败气泡当空占位撤掉。只有状态查询确认重试尚未受理时，才撤回本地重试占位并恢复原回答；状态未知不能据此重发已受理请求。

错误可附带 `diagnostics`：记录 PREPARING / COMPACTING / SENDING / TOOLS / FINALIZING 阶段，以及主请求和摘要请求是否到达 HTTP 发送边界。主请求未开始发送时，提示明确说明「主模型请求尚未发出」；摘要请求已尝试不代表主请求已发送，尝试发送也不证明供应商已收到。SSE、终态、状态和历史使用同一份错误；有部分正文的失败同样保留原因。旧错误缺少诊断时保持未知，不能把通用失败提示倒推成供应商报错。异常由请求所有者统一收尾一次，复核函数不先写终态而丢失后续具体错误。

上游并发等待结束后，实际 HTTP 发送前再次核对来源及取消状态；缓存兼容重发同样适用。请求构建失败或发送前取消不登记已发送用量、不替换主窗口快照，结果中的发送状态以最近实际发送的计划为准。窗口快照保留发送时冻结的来源版本，收尾不把旧请求套上编辑后的历史版本；新格式快照损坏不能通过 legacy 用量重建为当前版本。最终具体错误优先于旧 recovery 报错，重试次数继续展示，错误正文只显示一次。

执行时在原回复位置显示灰色折叠图标与「正在压缩上下文…」。检查点校验和 CAS 发布后保存完成进度，界面改为「上下文已自动压缩」，回答结束后继续保留；切换会话、查询轮次、重载历史或服务重建后也可恢复。状态使用独立的 `running / completed` 字段：结束运行不等于成功，停止或失败不能仅凭 `running=false` 显示完成标识。

主请求收到明确的窗口拒绝且本次尚无正文、思考或工具调用输出时，在原轮内最多进行两次压缩恢复：下一发送输入上限收紧至被拒请求估算的 75%，重新压缩、预检和复核后再发。工具已成功执行的闭合步骤继续保留；恢复不执行旧工具。已有部分响应、插话交付未确认、取消、来源变化或关闭自动压缩时不进入此路径。普通网络重试仍发送冻结正文。受保护输入无法缩小时明确失败，不能再次发送已知超窗正文。无输出且无 usage 的流式窗口拒绝释放预留执行额度，账目仍按未知结算。

摘要因 length / max_tokens 截断时，按完整原来源重做一次，要求更紧凑并在允许范围内调整输出；上限同时受本轮模型输出设置、4,096 Token 和剩余额度约束。仍截断则缩小来源组或完整分片，最多三次减量，所有调用共用每次准备 32 次 / 120 秒上限；截断片段从不发布，已经完整的候选与原视图继续遵循硬窗口回退规则。

检查点采用 continuation-v2 / payload schema 2，新增程序管理的 retained：完整写入回执记录 source / id / tool / status；模型只见按工具和状态计数、最近八条精确回执，摘要 receipts 返回空数组。QUEUED / RUNNING 只代表已接受，不冒充完成。原闭合步骤仍保留可核对的业务证据，步骤被整轮覆盖后其回执归属同步改为 TURN。模型 sources 仅提供近期最多 128 个可选标识，完整来源覆盖不依赖模型抄写。

用户约束保护来自组装器明确标记的用户正文和已接收补充，排除工具、助手和应用续接说明。规则识别否定、限制、改口、待办、常见精确数值或版本后保留完整原句与来源；短要求整条保留，长文本只保留命中的完整分句及其冒号后的内容。相同原句只保留最新来源，明确改口按先后顺序保留，不由程序擅自推断旧要求已撤销。最多 512 条、单条 2,048 字符、合计 4,096 估算 Token；超限不截半句、不静默遗忘，按安全回退或明确失败处理。该规则是额外保护，无法覆盖任意语言和隐含要求，不是语义无损保证；引用资料仍不增加授权。

旧 continuation-v1 缺少确定性保护字段，视为不可复用并从合格原历史重建，原记录不变、不自动改写旧摘要内容。新状态和来源共同加密、发布、校验与失效，不新增数据库表。标准轮次按 256 条元数据分页，正文最多每批 16 轮；已覆盖、跨代、删除或未完成的正文不加载。32 MiB / 16,384 轮限制只计需读取的正文，另保留 262,144 条元数据与 30 秒保护。TURN / STEP 来源按 256 条批量校验，版本查询只读 revision；旧 LEGACY 来源无版本列，检查点验证仍需核对原内容指纹，不承诺同等性能。

原生 compaction、后台预压缩、工具定义按需发现和分支会话树不作为第一阶段依赖。稳定系统前缀、稳定工具顺序和未变化历史先做好，协议缓存优化在真实兼容验证后扩展。
